Ordering findings, and the one probe that logs in

Three additions to the triage pipeline: CVSS as a second sort key, a ranked “start here” view that every surface shares, and an opt-in default-credential probe that reports itself as its own tier. This page explains how each one behaves, what it deliberately refuses to do, and what was actually verified.

1 — the rule

Confidence decides. CVSS only breaks ties.

A CVSS score says how bad a vulnerability would be if it applies. It says nothing about whether it applies to this service. So the ordering tuple is (confidence_rank, cvss_score) — and a candidate with no score sorts below a scored one at the same confidence, never above it. 

def rank_key(confidence, cvss_score=None):
    score = cvss_score if cvss_score is not None else -1.0   # no score ranks last
    return (CONFIDENCE_ORDER.get(confidence, 0), score)     # confidence is primary

One function, three consumers: the engine sorts each port’s candidates, the report re-applies it after reading SQLite, and the dashboard strip ranks whole hosts. They cannot disagree, because they ask the same function.

2 — the pipeline

Where each source enters, and where the ordering is applied

Why the report re-sorts

The dashboard and the exports read candidates back from SQLite, where rows come out in insertion order. If the ordering only existed inside the engine, a page reload would silently rebury the best candidate. So build_report() re-applies rank_candidates() on read.

3 — five tiers, two axes

“This version has a CVE” is not “this password works”

The four match tiers describe evidence about a banner. A credential the target accepted is evidence about configuration, and it is a fact rather than an inference — so it gets its own tier and its own colour instead of being dressed up as HIGH.

What the new tier does not change

The four original tiers keep their exact strings, labels and ordering, and the report never prints “DEFAULT CREDS confidence: 0” — the tier gets its own sentence and only when it happened. confidence is still the primary sort key, so an access finding ranks above a weaker match but a verified credential never claims to be a CVE match.

4 — CVSS

One score, taken from the strongest metric the record has

NVD sometimes publishes several metrics for the same CVE. The parser walks them in NVD’s own order of preference and stops at the first one present, so a CVE can never carry two conflicting severities.

Cache rows and schema drift

Cached NVD payloads outlive code changes. Reconstructing a cached record now filters to the fields the dataclass actually declares, so a row written before CVSS existed loads with no score instead of raising and killing the whole correlation run.

5 — the surfaced capability

“Start here” replaces walking a flat list of ports

The correlation summary, the dashboard strip and the report all render the same rows from models.start_here_rows(): one host each, its best candidate, ordered across the whole scan.

Why this is the capability worth having

A per-port list answers “what is on this port”. It does not answer “where do I look first”, and on a host with thirty open ports that question is the whole job. One ranked row per host, shared by data, report and UI, is the smallest thing that answers it — and it survives a reload because it is derived from stored candidates rather than from a live event.

6 — the opt-in probe

Connect, authenticate, stop

This is the one source that actively touches the target. It opens a TCP connection to a port the scan already saw open, tries a handful of published defaults, and reports what the service itself said. Nothing is uploaded, executed or read beyond the login handshake.

Curated pairs — a handful of published defaults, never a wordlist

Deliberate refusals
  • At most 5 attempts per port, with a hard per-attempt timeout, and it stops at the first success — this cannot become a lockout or a brute-force run.
  • An unreachable service costs one attempt, not five: five timeouts are one fact repeated.
  • SCRAM-SHA-256 and MySQL auth-plugin switching are declined with a reason rather than guessed at.
  • Offline/mock mode never probes — there is no real target to authenticate to.
